# ChiefDelphi 电气板块近期热门话题汇总（中文）

【数据采集时间】2026年5月12日

================================================================================
一、CANivore 故障与稳定性问题
================================================================================

1.1 CANivore 出现红色状态灯闪烁（状态码：USB连接异常）

多个队伍报告 CANivore 的 STAT 灯突然开始红色双闪，根据 CTRE 状态码表
示 USB 连接不良或无连接。重启 roboRIO 或重新上电可立即恢复，但问题会
在不确定的时间后再次出现。

已尝试的解决方案：
- 更换 CANivore 本体（部分有效）
- 更换 USB 线缆（CTRE 原装白色尼龙编织线效果较好）
- 给 USB 接口打热熔胶固定防震
- 从 PDH 额外引入 12V 冗余供电（避免 USB 供电中断导致整个 CAN 总线掉线）

根本原因分析（CTRE 官方回复）：
静电放电（ESD）事件可能导致 roboRIO 的 USB 端口 5V  rail 被关闭，两个
USB 端口会同时失效。建议使用屏蔽 USB 线缆以避免 ESD 干扰。

社区发现的重要线索：
- 某些 USB 存储盘（U盘）通过延长线连接时会引发 USB 端口掉电
- 屏蔽层未正确接地的延长线会导致屏蔽层悬空，加剧干扰
- 建议：将 U 盘直接插入 roboRIO，或使用以太网传输日志，避免 USB 延长线

成功解决方案（Nate_Laverdure 分享）：
- 添加 substantial 接地线
- 所有 USB 线缆加装屏蔽层并确保屏蔽层接地至电池负极
- USB 线缆加装铁氧体磁环
- 监控 roboRIO 内核日志中的 USB 状态变化和 ESD 检测事件
- 经过数小时练习测试，CANivore 不再掉线

================================================================================

1.2 CANivore 延迟和间歇性断开（设备在 Tuner X 中"幽灵消失"）

典型症状：CAN FD 总线出现严重延迟，随后整个总线断开。最奇怪的现象是
Phoenix Tuner 中 CANivore 本身仍然可见，但总线上的所有设备从列表中消失。
重新刷写 CANivore 固件有时能暂时"唤醒"系统，但延迟持续存在，最终再次掉线。

典型配置：4 个 SDS MK4I 转向模块（4x Kraken X60 + 4x Falcon 500），1x Pigeon 2.0

排查建议：
- 检查总线末端是否有正确的 120Ω 终端电阻（不要使用 PDH/PDP 1.0 作为终端，
  因为它们只支持 CAN 2.0，会导致 CAN-FD 总线报错）
- 检查线缆是否绞合且没有断裂
- 不要使用星型拓扑（star topology），长分支（stub）会导致 CAN FD 问题
- 如果必须使用星型拓扑，将未使用的分支修剪至 10cm 以下

实测案例：某队伍使用星型拓扑接入 13 个设备（Pigeon + 8 电机 + 4 CANcoder），
添加第 13 个设备后 CAN 总线崩溃。将分支修剪缩短后问题解决。

根本原因：通常是接线或终端问题。CAN FD 对布线问题比标准 roboRIO CAN 总线
敏感得多。如果 CANivore 检测到某个节点错误过多，可能会忽略该节点或关闭整个总线。

================================================================================

1.3 CANivore 无法识别设备

表现为 Tuner X 中看不到 Talon/Kraken 电机，或 CANivore 完全不识别任何设备。

排查清单：
- 确认极性正确（CAN_H / CAN_L 无反接）
- 检查所有接线端子（Wago 连接器、 vampire clamps）
- 检查电机内部接线
- 确认 CANivore 在 Tuner X 中已启用 USB 连接
- 尝试更换 USB 线缆
- 检查 12V 辅助供电是否正常（虽然非必需，但强烈建议）
- 确认 CAN 总线两端均有 120Ω 终端电阻
- 检查 CAN ID 是否有冲突（重复 ID 会导致看似线路问题）
- 测量总线电阻：断电后测量 CAN_H 和 CAN_L 之间应为 60Ω（两个 120Ω 并联）
- 检查是否存在 CAN 对机架短路或 CAN 对地短路
- 不要跳过任何步骤，即使"确定"某一步没问题

注意：设备在 roboRIO 总线上能工作，不代表接线没问题——roboRIO 总线对
不良布线更宽容，只是抑制了问题而非解决了问题。

================================================================================

1.4 CANivore 红灯常亮

根据 CTRE 文档，红色 CAN 灯表示"CAN 总线电压过低"，解决方案是确保设备
通过 USB 接收 5V 供电，并满足最低电压要求。

二、CAN 总线布线与拓扑结构
================================================================================

2.1 添加第7/8个 Kraken 电机后 CAN 通信崩溃

典型症状：接入第7个 Kraken X60 电机后，所有电机和 CAN 设备每隔 5-10
秒闪红灯。已尝试更换电机、更换线路、检查整个底盘 CAN 总线均无效。

网络拓扑参考：
- Pigeon 2（首个设备）
- 4x CANcoder
- 8x Kraken 电机
- 2x Neo 电机（Spark MAX，用于 intake）

关键发现：
- 当第7个 Kraken 替代 Neo（Spark MAX）位置时，问题复现
- Spark MAX（非 CAN-FD 设备）不能接在 CANivore 总线上

社区建议的排查步骤：
1. 确认所有电机 CAN ID 唯一，无重复
2. 验证 CAN 总线全环的连通性
3. 测量总线电阻：应为 60Ω（两端各 120Ω 并联）
4. 检查 CAN 总线占用率（utilization），考虑降低 Kraken 状态帧发送频率
5. 检查线缆长度，过长会导致有效占用率异常升高
6. 逐个隔离电机测试，特别是引发故障的"第7个"电机本身是否有 CAN 故障

================================================================================

2.2 CAN 总线故障导致 Pigeon 陀螺仪异常

在季后赛比赛中出现：自动阶段结束后机器人突然停止移动。排查发现与 CAN
总线故障有关，添加新设备后 Pigeon 2.0 出现通信异常。

三、CTRE 与 REV 混合 CAN 布线架构
================================================================================

核心原则：

1. CANivore 仅支持 CTRE 产品（CAN-FD 总线）
   - Kraken、Talon FX、CANcoder、Pigeon 2.0 等 CTRE 设备可接 CANivore
   - REV 产品（Neo、Spark MAX）不支持 CAN-FD，不能接在 CANivore 总线上

2. roboRIO 总线支持 CAN 2.0 + CAN-FD 回退（fallback）
   - 所有 FRC 可用的 CAN 电机和传感器都可以接在 roboRIO 总线上
   - 但需要手动控制总线负载

3. 混合布线架构建议：
   - CANivore 总线（CAN-FD）：仅接 CTRE 设备
     → 通过 USB-C 接入 roboRIO
   - roboRIO 总线（CAN 2.0）：接 REV 设备 + 必要时接 CTRE 设备
     → 利用 roboRIO 内置的 CAN 2.0 端口

4. 布线注意事项：
   - CAN 总线必须从 roboRIO 连到 PDP/PDH（即使所有电机都在 CANivore 上）
   - CANivore 不能接在 PDP/PDP 1.0 作为终端，因为 PDP 1.0 不支持 CAN-FD
   - 即使 PDP 2.0 没有 CAN 功能，仍需遵守规则要求

================================================================================
四、双 CANivore 配置（非常规/非官方支持）
================================================================================

有队伍尝试在同一条 CAN 总线上接入两个 CANivore：
- 第一个 CANivore 通过 USB 接入 roboRIO（总线名 canivore）
- 第二个 CANivore 通过 USB 接入协处理器（coprocessor，总线名 secondcan）

目标：让 roboRIO 和协处理器同时读取同一组 CTRE 设备（如 Pigeon 2.0、
电机等），实现低延迟的航向角读取和里程计更新。

实际现象：
- 协处理器上必须将 CAN 总线名设为第二个 CANivore 的名称（"secondcan"）
  才能读取设备
- 第二个 CANivore 插入 USB 时，Tuner X 会停止显示该总线上的设备
- 基本功能正常，但存在隐患

CTRE 官方立场：
这不是官方支持的配置。目前唯一支持的双 CANivore 模式是：
- 一个设为 "enable-only"（通常在 roboRIO 端，仅用于使能设备）
- 另一个运行 Phoenix 诊断服务器，执行实际控制和运算

限制条件：
1. 必须有一个设为 "enable-only"
2. 一个机器人程序必须禁用 Phoenix 诊断服务器
3. enable-only 端的设备时间戳无效（会匹配另一系统的时间戳）
4. 控制指令、配置写入、设备 setter（如 setYaw）只能从其中一个系统发起

建议替代方案：
- 协处理器与 roboRIO 之间使用以太网通信（NetworkTables）
- 或直接用 USB/以太网连接协处理器，通过标准网络协议传输数据
- CAN-FD 的大帧和高波特率优势在 roboRIO 端无法体现

五、2026 赛季电源分配设计（PDP 2.0 + MPM）
================================================================================

5.1 问题背景

队伍计划使用 PDP 2.0 作为主电源分配设备，设计包括：
- 20 个电机
- REV Servo Hub（用于 shooter hood 调节）
- REV Mini Power Module（MPM，用于低电流设备）
- 3 个 Limelight 视觉设备
- roboRIO 和无线电按标准方式供电

问题在于：分配完电机、roboRIO、无线电、视觉设备后，MPM 的低电流输出
端口不足以支撑剩余所有设备（Servo Hub、传感器、LED 等）。

================================================================================

5.2 规则解读

根据 2026 规则：
- R621：每个电机控制器和 Servo Hub 必须独占一个断路器（breaker）
- R615 / R617：roboRIO 和无线电也必须各独占一个断路器

这意味着：20 个电机 + 1 个 Servo Hub + roboRIO + 无线电 = 23 个端口已被
占用。PDP 2.0 剩余的 3 个端口（假设总端口足够）中，只有 1 个可用于其他
CUSTOM CIRCUITS（传感器、协处理器如 Limelight 等）。

CUSTOM CIRCUITS 规则：
- R621 允许从单个 breaker 引出无限数量的 CUSTOM CIRCUITS
- 规则未限制如何在 CUSTOM CIRCUITS 内部进行电源分配
- MPM 是 CUSTOM CIRCUITS 内部分配电源的理想工具

================================================================================

5.3 解决方案与最佳实践

方案一：双 MPM 并联供电
- 将两个 MPM 的输入电源线并联（Y-split）
- 从同一个 PDP 高电流输出端口（20A-40A 保险丝）供电
- 这是合法且电气上可接受的，只要不超电流限制

方案二：Inline Power Tap（直插式电源分接头）
- Kraken PowerPole 转接板：带 0.5A 自恢复保险丝
- ReFire Inline Power Tap：带 2.6A 多路保险丝，可带 2 个 Limelight

方案三：直接从电机控制器供电
- 部分电机控制器有传感器供电端口，可为低功率设备供电

方案四：VRM 供电
- 从 VRM 12V2A 端口为 CANivore 等设备供电（作为冗余）

================================================================================

5.4 供电安全与检查建议

- 所有离开连接器（connector）的线缆必须有应力释放（strain relief）和
  "service loop"（备用松弛段），防止被扯出
- 建议在关键连接器上打一滴热熔胶防震
- 使用 Wago 连接器时，注意高电流电路的正确使用方法
- 如果使用非自恢复保险丝，务必在机器人推车上备好备用保险丝
- PDP 2.0 无电流监测/记录功能，建议手动记录各设备的电压/电流数据
- 主电池线缆必须压接牢固、连接紧密
- 电池必须保持良好状态并充满电
- 齿轮比和电机电流限制需合理选择，避免瞬时电流过大
- roboRIO 和无线电绝对不能共用 PDP 端口——这是最关键的两个组件，
  需要最大程度的冗余保护

================================================================================
六、终端电阻与总线测量要点
================================================================================

- CAN 总线必须在两端各接 120Ω 终端电阻
- roboRIO 和 PDH 内置了终端电阻（使用时默认启用）
- CANivore 有内置终端电阻，可通过软件启用/禁用
- 测量总线电阻：断电后测量整个环路应为 60Ω（两个 120Ω 并联）
- CAN-FD 对终端电阻缺失非常敏感，必须确保终端电阻存在
- 不要同时使用 PDH/PDP 1.0 作为 CANivore 总线的终端（不支持 CAN-FD）

================================================================================
七、USB 线缆与 ESD 防护最佳实践
================================================================================

- CTRE 自 2024 年 6 月起随 CANivore 附赠屏蔽 USB A-C 线缆
- 如更换线缆，务必确认新线缆是否为屏蔽线
- USB 接口两端都建议打热熔胶固定防震
- 避免使用 USB 延长线接存储设备，尤其是屏蔽层未正确接地的延长线
- 直接使用短款 U 盘插入 roboRIO，或通过网络（AdvantageScope / DataLogTool）
  传输日志
- 为所有 USB 线缆添加屏蔽层并确保接地
- USB 线缆加装铁氧体磁环（ferrite choke）
- 从 PDH 引入 12V 冗余供电至 CANivore（强烈建议）
- 监控 roboRIO 内核日志检测 ESD 事件

================================================================================
八、总结与建议
================================================================================

1. CANivore 稳定性：
   - 优先使用 CTRE 原装屏蔽 USB 线缆
   - USB 接口打热熔胶固定
   - 从 PDH 引入 12V 冗余供电（强烈建议）
   - 避免使用 USB 延长线接存储设备，直接用短 U 盘或以太网传输日志
   - 加装接地线和铁氧体磁环

2. 混合设备布线：
   - CTRE 设备优先走 CANivore 总线（CAN-FD）
   - REV 设备（Spark MAX/Neo）必须走 roboRIO 总线（CAN 2.0）
   - 严禁将非 CAN-FD 设备接入 CANivore 总线

3. 电源分配：
   - PDP 2.0 端口紧张时，利用 CUSTOM CIRCUITS 规则灵活分配
   - MPM 可以并联使用，增大低电流端口数量
   - 关键设备（roboRIO、无线电）不要共享断路器，保持冗余
   - 准备好备用保险丝和快速更换方案

4. 故障排查流程：
   - 检查 CAN ID 唯一性 → 检查终端电阻 → 测量总线电阻 → 检查线缆长度
     → 逐个隔离设备测试 → 检查总线占用率 → 考虑降低状态帧频率
   - 不要跳过任何检查步骤
   - CANivore 上能工作不代表接线正确，roboRIO 总线更宽容

5. 总线拓扑：
   - 优先使用菊花链（daisy chain），避免星型拓扑
   - 如必须用星型拓扑，分支长度控制在 10cm 以内
   - 确保线缆绞合，无裸露连接器
